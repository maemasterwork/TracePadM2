# راهنمای مدیر (فارسی)

راه‌اندازی کامل در [../deployment.md](../deployment.md) است. این صفحه فهرست کارهای مدیر است. دو نوع مدیر هست: **مدیر پلتفرم** (استقرار را اداره می‌کند) و **مدیر سازمان** (یک مدرسه یا شرکت را درون آن).

## مدیر پلتفرم
**یک‌بار راه‌اندازی**: پروژهٔ Supabase را بسازید، مهاجرت‌ها را اجرا کنید، کد دعوت معلم را بگذارید، ایمیل (SMTP سفارشی) و نشانی سایت را تنظیم کنید، سایت را با سرآیندهای لازم بسازید و میزبانی کنید، سپس فهرست راه‌اندازی اول را انجام دهید.

**معلم‌ها**: کد دعوت را بدهید (محرمانه نگه دارید؛ با یک دستور SQL عوضش کنید). آن‌ها در «حساب کاربری» معلم می‌شوند. بدون کد هیچ‌کس از راه برنامه معلم یا مدیر نمی‌شود؛ `platform_admin` و `content_editor` فقط با SQL و به‌عنوان مالک پایگاه داده داده می‌شوند:
`update public.profiles set role = 'platform_admin' where id = (select id from auth.users where email = '...');`

**زبان‌آموزان بدون ایمیل** با `username@<VITE_USERNAME_DOMAIN>` وارد می‌شوند. اگر رمزشان را فراموش کردند، در Supabase بخش *Authentication ← Users* بازنشانی کنید. برای حذف، کاربر را همان‌جا پاک کنید (پیشرفتش هم پاک می‌شود).

**زبان‌آموزان زیر ۱۳ سال** نمی‌توانند خودشان ثبت‌نام کنند. در *Authentication ← Users ← Add user* از `username@<VITE_USERNAME_DOMAIN>` استفاده کنید، رمز بگذارید، تأیید خودکار را تیک بزنید و در فراداده `{"full_name": "...", "username": "...", "age_band": "under13"}` بگذارید. (در محیط ساخت امتحان نشده؛ اول یک حساب را امتحان کنید.) ساخت گروهی و برگهٔ مشخصات ورود **ساخته نشده**.

**درخواست‌های حریم خصوصی**: زبان‌آموزان داده‌شان را در «حساب کاربری» دریافت و پاک می‌کنند. نقش‌های پلتفرم نمی‌توانند خود را حذف کنند؛ دستی حذف کنید.

**پرچم‌های ویژگی و گزارش ممیزی**: `feature_flags` و `audit_log` فقط برای مدیران پلتفرم و فعلاً با SQL قابل خواندن و نوشتن‌اند. گزارش ممیزی حذف حساب، تغییر نقش و پرچم، **تغییر دستی نمره و نتیجه‌های برگردانده‌شده** را ثبت می‌کند.

**نمونهٔ نمایشی**: `psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f supabase/demo/demo_seed.sql` «Tracepad Demo School» را با یک کلاس و ۳۰ زبان‌آموز شبیه‌سازی‌شده بارگذاری می‌کند (بدون رمز؛ هیچ‌کس نمی‌تواند با آن‌ها وارد شود). برای گشت‌وگذار، عادی ثبت‌نام کنید و `psql ... -v email=you@example.com -f supabase/demo/adopt.sql` را بزنید. با `supabase/demo/remove.sql` همه چیز پاک می‌شود. نمونه را در پایگاه دادهٔ تولیدی که کلاس واقعی دارد بارگذاری نکنید.

**افزودن درس**: کار محتوایی است؛ README را ببینید. `npm run content:build` را اجرا و دوباره مستقر کنید.

**پشتیبان‌گیری و پایش**: پشتیبان Supabase را روشن و یک بازیابی را آزمایش کنید. هنوز پایش خطا و تنظیم نگهداری داده نداریم (مرحلهٔ ۵).

## مدیر سازمان
۱. **تدریس ← ساخت سازمان** (نام؛ شما مدیرش می‌شوید). صفحهٔ سازمان **کد دعوت** را نشان می‌دهد (هر زمان کد تازه بسازید، قبلی از کار می‌افتد).
۲. معلم‌هایی که حساب معلم دارند کد را در **تدریس ← پیوستن با کد دعوت** وارد می‌کنند. در فهرست اعضا می‌توانید کسی را مدیر، معلم یا حذف کنید. معلم می‌تواند خودش سازمان را ترک کند.
۳. **سقف صندلی** اختیاری: بیشینهٔ زبان‌آموزان متمایز در همهٔ کلاس‌های سازمان. وقتی پر شود به زبان‌آموز گفته می‌شود از مدیر مدرسه بپرسد.
۴. **گزارش**: یک ردیف برای هر کلاس (معلم، زبان‌آموزان، تکلیف‌ها، تحویل‌ها، میانگین، آخرین تحویل، بایگانی). هرگز یک زبان‌آموز را نشان نمی‌دهد. شما خودکار معلم آن کلاس‌ها نیستید؛ معلم می‌تواند شما را هم‌معلم کند.
۵. معلم‌ها هنگام ساخت کلاس سازمان را انتخاب می‌کنند.
